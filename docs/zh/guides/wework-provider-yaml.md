# WeWork 本地 Provider 与 YAML 配置

在设置的模型页面中，“服务连接与 YAML”管理本地自定义入口。云端下发的模型和 Codex 账号来源仍通过原有链路管理，不会写进本地文件。

## 使用

添加服务连接，填写名称、Base URL 和协议。API Key 只输入一次，留空保存表示保留原 Key，清除必须显式勾选。批量添加支持每行一个上游模型 ID 或逗号分隔；也可以保存连接后获取模型列表并勾选添加。模型列表获取不表示工具调用已通过验收。

页面默认使用用户数据目录下的 `model-config/model.yml`。可通过“选择 YAML 文件”绑定自选文件；“打开文件编辑”调用系统编辑器。外部修改后点击“重新加载”。页面保存写回同一文件；读取后的文件被外部修改时，会阻止旧页面覆盖它。语法错误时运行目录保留最后有效版本，页面显示错误。文件加载不触发付费模型测试。

`wework/model.example.yml` 是无凭据的示例。`id` 是稳定的本地标识，`model_id` 是实际发送给上游的 ID，`display_name` 是显示名称。模型继承连接默认协议与路径，可以在高级设置或 YAML 中覆盖。模型高级能力通过 `settings` 保留旧版能力字段。

## 旧配置与凭据

“迁移旧模型”会把相同地址、协议、路径和 Key 的旧条目整理成共享连接，并保留原模型 ID。迁移保存成功后才移除旧副本。建议迁移前备份现有用户数据，避免把旧配置和文件长期作为两份可编辑主副本。

页面输入的 Key 通过现有 Electron `SecureValueStore` 加密存储，文件只保存 `api_key_ref`。执行准备时解密，可信工作台内存中会持有必要的运行凭据，但不会把这些解析结果写回 `localStorage` 或变更事件。该加密存储不是 macOS Keychain，文件和本机加密密钥仍需按用户数据妥善保护。

手动 YAML 也支持 `api_key` 明文，但不要把含 Key 的文件提交到版本库、上传或分享。凭据引用只在创建它的设备上有效，换设备后要重新输入 Key。复制 YAML 不是云端模型发布操作。

## 云端与运行任务

本功能只改变本地配置来源，不改云端目录 API、目录合并身份或执行设备路由。自定义模型继续使用 `local-model:<id>` 和 `model-interface` 身份。文件加载、页面保存不会上传全量凭据。远程任务仍使用已有执行准备、目录同步与确认流程。

模型能力变更仍需现有 Codex catalog 同步；运行中任务不因页面保存被强制重启。目录未准备好时沿用现有空闲重启或确认流程。

## 回归检查

自动化覆盖文件校验、共享凭据、保留/轮换/清除 Key、并发编辑冲突、错误恢复、旧 ID 迁移、页面批量添加和既有本地模型逻辑。构建 CI 另运行现有云端混合目录测试和类型检查。安装包与真实模型执行属于独立验收，不要把单元测试通过等同于全部运行场景已验证。
